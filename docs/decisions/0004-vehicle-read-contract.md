# ADR-0004: 차량 조회 계약과 요청 생명주기

- 날짜: 2026-11-02
- 상태: 채택 (2026-11-03, 담당자가 알린 상대 개발자 합의. COM-16 PR에 기록)

## 맥락
COM-18·19·20이 구현을 시작하려면 양쪽이 지킬 규칙이 필요하다. 기존 규칙은 PoC 코드에만 있고 도구 4개만 다룬다. 범위를 Vehicle SDK의 공개 조회 전체로 넓히기로 했다. Pleos 문서는 `e is VehicleException` 분기를 안내하지만, 배포 AAR에서는 이 클래스가 난독화되어 있고 실제 조회 실패는 일반 `Exception`의 문자열로 온다.

## 결정
[계약 문서](../../contracts/vehicle-read/CONTRACT.md), `catalog.json`, 공용 fixture를 Android와 Node의 단일 기준으로 삼는다. ADR-0002의 stdio·loopback·ADB 경로는 유지하고 세부 wire만 `/v3/vehicle-read`로 바꾼다.

- 범위는 97개 공개 조회 속성과 도구 22개다. 기존 4개가 필수이고 18개는 실행 검증 후 채택한다.
- VIN, 구독, 제어, 비공개·Deprecated API는 제외한다.
- 동시 조회는 1건이다. 큐 없이 BUSY로 거절하고 자동 재시도하지 않는다.
- SDK 실패는 타입이 아니라 원인 체인의 메시지로 분류한다.

## 대안
- 도구를 범용 2개로 줄이면 목록은 작지만 AI가 속성 ID를 먼저 조회해야 한다. API마다 1개씩 두면 약 100개가 되어 도구 선택이 어려워진다.
- PoC처럼 timeout 때 항목을 전부 버리면 단순하지만, 큰 도메인에서 이미 받은 값까지 잃어 FR-VEH-06과 어긋난다.

## 결과
fixture를 양쪽 테스트가 읽으므로 한쪽만 바꾸면 CI가 실패한다. 카탈로그는 SDK 클래스와 리플렉션으로 대조하므로 SDK 버전을 올리면 다시 확인해야 한다. 카탈로그 등재는 동작 보장이 아니며 전 속성 실행 검증은 COM-20에서 한다. 큰 도메인이 10초 안에 끝나는지는 측정 전이다. 요구사항 3.4.1은 표시만으로 필수 범위를 넓히지 않으므로, 18개 후보를 필수로 올리려면 요구사항을 먼저 고쳐야 한다.
