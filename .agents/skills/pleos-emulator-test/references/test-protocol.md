# 테스트 프로토콜

## 관찰 계층

각 계층은 자기 값만 증명한다. 시나리오마다 무엇을 대조할지 먼저 정한다.

| 계층 | 관찰 지점 | 증명하는 것 | 증명하지 못하는 것 |
| --- | --- | --- | --- |
| L0 | Console `GET /vehicle/state` | Console이 보유한 값 | VHAL, SDK 반영 |
| L1 | 앱 UI, 앱 알림(`notifications.txt`) | 화면·알림에 표시된 값. Pleos_PA는 Foreground Service 알림으로 연결 상태를 보인다 | SDK 응답, 값의 최신성 |
| L2 | SDK 콜백 (logcat, 앱 진단 화면) | SDK가 해당 앱에 돌려준 값 | 앱 가공 후 출력 |
| L3 | Bridge `POST /v2/vehicle-read` | 앱이 내보낸 값 | MCP 변환 |
| L4 | 로컬 MCP 도구 호출 | MCP 입출력 | 외부 AI 동작 |
| L5 | ChatGPT, Claude 앱 | 외부 AI의 도구 선택과 답변 | 별도 E2E로 분리, 사람이 수행 |

내비 시나리오는 L0·L3 대신 N1(순정 화면)·N2(판독 앱 콜백)·N4(MCP)를 쓴다([pleos-specific.md](pleos-specific.md#관찰-계층-내비)).

L0~L4는 로컬 통합 테스트이고 L5만 외부 AI E2E다. 로컬 통과를 AI 앱 성공으로 보고하지 않는다. L5의 실패는 가장 앞에서 실패한 단계 하나로 분류한다: 도구 선택 실패, 연결 실패, SDK 조회 실패, AI 응답 해석 실패, 시간 초과.

## 상태 판정

| 상태 | 조건 |
| --- | --- |
| `PASS` | 시나리오가 정한 모든 계층에서 기대값과 실제값이 일치하고 증거 파일이 있다 |
| `FAIL` | 실행했으나 값이 다르거나 기대 동작이 일어나지 않았다 |
| `BLOCKED` | 전제 미충족으로 실행하지 못했다. 막은 조건을 적는다 |
| `NOT_RUN` | 실행하지 않았다. 이유를 적는다 |

- 일부 계층만 확인했으면 전체를 PASS로 적지 말고 계층별로 쓴다. 예: `L0·L2 PASS, L4 NOT_RUN`.
- 수신 시각은 차량 측 측정 시각이 아니다. 최신성의 근거로 쓰지 않는다.
- 빈 응답의 `0`은 값이 아닐 수 있다. 예: 목적지 없을 때 `remainTime=0`. 의미를 확인하고 판정한다.
- 원인을 모르면 `원인 미확정`과 확인한 사실, 다음 확인 방법을 적는다.

## 증거 수집

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agents\skills\pleos-emulator-test\scripts\collect-evidence.ps1 -Serial <serial> -RunId <시나리오-날짜> -Label <before|after-open|...> -Package <package>
```

`build/pleos-emulator-test/<RunId>/<Label>-<시각>/`에 저장된다. 이 경로는 git에서 제외되어 있다.

| 파일 | 내용 |
| --- | --- |
| `screen.png` | 전체 화면 |
| `ui.xml` | 포커스 창의 UI 계층. 전체 창은 `android layout -o`로 따로 저장 |
| `layout.json` | `uiautomator`가 Android CLI 계측에 막혔을 때 대신 저장한 전체 창 계층 |
| `ui-summary.txt` | `layout.json` 또는 `ui.xml`에서 뽑은 요소 표(번호, 창, 중심 좌표, 동작, 이름). 판독용 요약이며 원본이 증거다 |
| `notifications.txt` | `-Package` 앱의 알림(채널, flags, 제목·본문). 다른 앱 알림은 개인정보가 있을 수 있어 담지 않는다 |
| `tag-<태그>.txt` | `-LogTag`로 지정한 도구 로그 |
| `top-activity.txt` | 재개된 Activity |
| `console-state.json` | L0 값 |
| `logcat.txt` | 패키지 실행 중이면 해당 pid, 아니면 전체 tail |
| `meta.json` | 기기, 사용자, 수집 항목 상태 |

조작 전후로 각각 실행한다. Bridge 응답과 MCP 응답은 수집 대상이 아니므로 보고서에 그대로 옮긴다.

- 도구 로그(예: nav-place-check의 `PlaceCheck`)는 `-LogTag PlaceCheck`로 `tag-<태그>.txt`에 따로 저장한다.
- 구간은 `-Since '<MM-DD HH:MM:SS.mmm>'`로 자른다. `adb logcat -c`는 쓰지 않는다.
- 보고에는 증거 폴더 경로를 적는다. 임시 스크립트로 모은 파일은 `meta.json`이 없으므로 환경을 보고서에 직접 적는다.

## 비밀정보

AI 화면 근거는 도구 이름, 인자, 최종 답변을 기록표에 텍스트로 옮겨 적는 것을 기본으로 한다. 캡처가 필요하면 대화 영역만 잘라 계정 정보와 대화 목록을 빼고 공유 전에 실행자가 확인한다.

- 스크립트가 텍스트에서 Bearer 토큰, `token=`류 값, API 키 접두사, JWT, 이메일, 휴대폰 번호를 가린다.
- **스크린샷과 사람 이름은 가려지지 않는다.** 개인 일정이나 연락처가 보이는 화면에서는 `-NoScreenshot`을 쓰고 UI 파일도 확인한다.
- 인증된 ChatGPT, Claude 화면이나 외부 서비스 토큰은 수집하지 않는다.
- **위치:** 내비 로그와 화면의 남은 거리·시간은 에뮬레이터 위치(가상 GPS)에서 잰 값이다. 여러 장소의 값을 모으면 위치를 역산할 수 있으므로 저장소·Linear·PR에는 옮기지 않는다. 장소의 좌표·이름·장소 ID와 판정만 옮긴다.
- **순정 내비 최근 목록:** 검색창을 열면 "최근"에 이전 검색·목적지가 보인다. 다른 사람이 쓴 에뮬레이터면 스크린샷을 공유하기 전에 확인하거나 자른다.
- 공유 전에 증거 폴더를 직접 확인한다. 마스킹은 패턴 기반이라 누락될 수 있다.

## 보고 양식

시나리오마다 작성한다.

```markdown
### <시나리오 이름>: <PASS|FAIL|BLOCKED|NOT_RUN>

- 환경: <AVD/API, serial, 사용자, Vehicle·Navi Service 버전>
- 대상 앱: <패키지, 버전, SDK 버전. PoC인지 Pleos_PA인지>
- 초기 조건: <조작 전 계층별 값>
- 수행한 조작: <도구와 명령 순서>
- 기대 결과: <계층별 기대값>

| 계층 | 기대 | 실제 | 판정 |
| --- | --- | --- | --- |
| L0 | | | |

- 증거: <폴더 경로>
- 복구: <복구한 상태, 남은 변경>
- 실패 원인·재현 방법: <해당 시. 미확정이면 그렇게 적음>
```

### 반복 실행

같은 조작을 대상만 바꿔 반복하면(예: 장소 4곳 × 2회) 환경·판독 앱·조작·기대값을 한 번만 적고 실행은 한 줄씩 쓴다.

```markdown
### <시나리오 이름>: <전체 상태>

- 환경, 대상 앱, 조작, 기대 결과: <위 양식과 같이 한 번>

| 회차 | 대상 | 시각(UTC) | 계층별 실제 | 복구 | 판정 |
| --- | --- | --- | --- | --- | --- |
| 1 | <키> | | N2 좌표 차이 0, N1 일치 | 목적지 없음 | PASS |

- 증거, 실패 원인: <위 양식과 같이>
```

마지막에 시나리오별 상태 표와 미검증 항목을 요약한다. 저장소 PR에 올릴 때는 일회성 결과를 PR 본문에 쓰고 비밀정보를 넣지 않는다.
